1. PROJECT OVERVIEW
-------------------
Project Title : Solize (Solar Plant Analyzer)
Type          : Standalone Desktop Software Application (Full-Stack & Data Analytics)
Domain        : Renewable Energy Analytics / Software Engineering
Target OS     : Microsoft Windows (Offline Native Executable)

Solize is an offline-first, enterprise-grade desktop software platform designed for solar power plant operators, performance engineers, and management teams. The application automates the ingestion of raw, multi-sheet operational Excel logs generated by solar inverters and weather stations, performs analytical computations on plant efficiency, and auto-generates client-ready executive reports in PDF and Microsoft Word (.docx) formats.


2. PROBLEM STATEMENT & OBJECTIVES
---------------------------------
Problem Statement:
Solar energy operational logs are typically exported as large, unstructured Excel files containing missing records, irregular date ranges, and noise. Manually processing these files to calculate key metrics—such as Performance Ratio (PR), Specific Yield, Capacity Utilization Factor (CUF), and degradation rates—takes hours of manual labor per reporting cycle and is prone to human error.

Key Objectives:
- Develop a robust data parsing pipeline that gracefully handles incomplete or corrupted Excel files.
- Compute standardized solar performance metrics and visualize trends in real-time.
- Automate report generation to produce formatted PDF and DOCX reports instantly.
- Package the entire web application (React + FastAPI) into a single, zero-dependency Windows desktop executable (.exe) with a native installer (.setup).


3. SYSTEM ARCHITECTURE & TECHNICAL STACK
----------------------------------------
The project follows a decoupled client-server architecture packaged locally into a standalone desktop application.

A. Frontend Architecture:
   - Framework  : React (Vite) with TypeScript
   - UI/Styling : Custom Dark Theme CSS & Inter Typography
   - Visualization: Recharts (Interactive Generation Curves, Loss Breakdowns, Degradation Charts)
   - HTTP Client: Axios (REST API communication)

B. Backend Architecture:
   - Framework  : Python 3.9 + FastAPI (Asynchronous REST API)
   - Data Engine: Pandas & NumPy (Excel parsing, time-series aggregation, math computations)
   - Database   : SQLite via SQLAlchemy 2.0 ORM
   - Reporting  : ReportLab (PDF layout engine) & python-docx (Word document compilation)

C. Desktop Packaging & Deployment:
   - Desktop Wrapper: PyWebView (Binds FastAPI server to Windows Native WebView2 / Edge Chromium engine)
   - Executable Build: PyInstaller (Bundles Python environment, FastAPI server, and compiled React dist into solizer-backend.exe)
   - Installer Wizard: Inno Setup (Generates Solizer_Setup.exe for one-click installation)


4. KEY MODULES & IMPLEMENTATION DETAILS
---------------------------------------
Module 1: Data Ingestion & Validation
- Parses raw inverter and weather station Excel logs regardless of missing rows (handles incomplete annual datasets gracefully).
- Validates data types and filters out corrupted or NaN (Not a Number) parameters before committing to SQLite storage.

Module 2: Analytics & KPI Computation Engine
- Calculates key operational parameters:
  * Performance Ratio (PR %)
  * Specific Yield (kWh/kWp)
  * Capacity Utilization Factor (CUF %)
  * Inverter-level Efficiency & String Loss Breakdowns
  * Multi-year Solar Module Degradation Rates

Module 3: Interactive Visualizations
- Real-time performance dashboard featuring dynamic date range filtering, inverter comparison views, and anomaly alert notifications.

Module 4: Automated Executive Reporting
- Auto-generates structured performance reports featuring cover pages, plant metadata summaries, KPI tables, performance charts, and automated maintenance recommendations.

Module 5: Standalone Desktop Packaging & Data Security
- Encapsulates database files under user-specific Windows roaming directory (%APPDATA%\Solizer) to prevent Windows permission errors and ensure data persists securely offline.


5. TECHNICAL CHALLENGES & SOLUTIONS
-----------------------------------
Challenge 1: Handling Missing / NaN Values in Database Operations
- Issue: Floating-point NaN values in raw Excel files broke SQL DELETE and INSERT queries during re-import operations.
- Solution: Implemented pre-ingestion cleaning using Pandas dropna/fillna routines and explicit type casting before triggering SQLAlchemy ORM operations.

Challenge 2: Converting Web Application to Standalone Desktop App
- Issue: Users required a native application that opens in its own window without requiring external browsers (Chrome/Edge) or background console windows.
- Solution: Integrated PyWebView to spawn a native 1280x720 desktop window. Configured PyInstaller spec files with console=False and bundled static frontend assets into FastAPI.

Challenge 3: Windows MIME Type Registry Issues
- Issue: On certain Windows machines, registry entries caused JavaScript assets (.js) to be served as text/plain, resulting in a dark blank screen.
- Solution: Explicitly registered MIME types (application/javascript, text/css) inside FastAPI and created custom middleware to enforce exact headers.
